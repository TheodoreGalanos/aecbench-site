title: Backends
description: A Harbor execution backend places each trial in a container or sandbox on the selected compute platform.
---

`aec-bench run` uses one execution path. It builds a Harbor job, dispatches the job through Harbor, waits for completion, and imports the results into the ledger. `--backend` selects the Harbor execution environment; all backend values use the same aec-bench runner.

Use `aec-bench run-local` when you need an in-process development path on the local host.

## Execution paths

| Command | Runtime boundary | Result handling |
|---------|------------------|-----------------|
| `aec-bench run` | Harbor environment | Dispatches the job and imports the completed Harbor job directory |
| `aec-bench run-local` | Local host process | Runs one task and imports the local result unless `--no-import` is set |

Both paths use the selected agent harness and the same task-owned verifier, which defines correctness in every environment.

## Provider boundary

Provider packages translate model, tool, and runtime protocols. They can capture provider evidence, but they do not own task selection, task meaning, or scoring. Task-specific branches belong with the task or world, not in a provider package.

Each runtime attestation refers to one retained provider evidence manifest. Keyless tests can prove the protocol shape without credentials. Live-provider qualification is a different claim and needs evidence from the real provider route. Passing keyless tests does not qualify a live provider.

## Available Harbor environments

`aec-bench run --backend` accepts five values:

| Backend | Where trials run | Configuration owner |
|---------|------------------|---------------------|
| **`modal`** | Modal containers | Harbor |
| **`docker`** | Local Docker daemon | Harbor |
| **`e2b`** | E2B sandboxes | Harbor |
| **`daytona`** | Daytona workspaces | Harbor |
| **`morph`** | Morph Cloud instances | AEC-Bench Harbor environment binding |

Install the Harbor execution extra before using these environments:

```bash
pip install "aec-bench[execution]"
```

Harbor owns the native `modal`, `docker`, `e2b`, and `daytona` environment implementations. Their credentials and service configuration follow the Harbor and provider setup. AEC-Bench validates the selected backend before dispatch; other values are rejected.

## Selecting an environment

For a one-task run, pass the backend directly:

```bash
uv run aec-bench run tasks/electrical/voltage-drop \
  --model "<model-id>" \
  --backend docker
```

For a manifest-driven run, use `compute.backend`:

```yaml
compute:
  backend: modal
  resource_limits:
    n_concurrent_trials: 4
  timeout_override: 600
```

`n_concurrent_trials` configures the local Harbor orchestrator. `timeout_override` applies an agent timeout override to the generated Harbor job.

Use `--dry-run` for planning: validate task selection and inspect the trial plan.

```bash
uv run aec-bench run --config experiment.yaml --dry-run
```

## Morph Cloud through Harbor

Morph uses the same Harbor dispatch and import path as the native environments, with an AEC-Bench environment binding that translates Harbor operations into Morph Cloud calls.

Install both optional extras and set `MORPH_API_KEY`:

```bash
pip install "aec-bench[execution,morph]"
export MORPH_API_KEY="<your-key>"
```

Then select `morph` as the backend:

```bash
uv run aec-bench run tasks/electrical/voltage-drop \
  --model "<model-id>" \
  --backend morph
```

Harbor still owns task staging, agent invocation, artefact collection, and verifier invocation. The Morph provider binding owns the environment operations.

## Local development

`run-local` creates a temporary workspace, runs one agent harness on the host, runs the verifier, and imports the result. It is useful for harness iteration and verifier debugging because failures remain on the local process boundary.

```bash
uv run aec-bench run-local tasks/electrical/voltage-drop \
  --model gpt-4.1-mini \
  --harness direct
```

`run-local` executes on the host. Use a Harbor environment when the task must run inside a controlled container or remote sandbox.

The installed library exposes the fixed backend set above. Add a new execution platform at the Harbor environment composition boundary and register it as a supported CLI value.
