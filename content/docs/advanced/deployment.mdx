For normal experiment runs, aec-bench builds a Harbor job config from the experiment manifest, invokes the Harbor CLI, locates the produced job directory, and imports its trial results into the ledger.

The public `aec-bench run` flow is synchronous. The command returns after Harbor finishes and the import step completes.

## Where Harbor sits

Harbor is the execution boundary around the task, agent harness, and verifier. It does not replace any of them.

| Layer | Responsibility |
|-------|----------------|
| **AEC-Bench planner** | Selects tasks and expands agents and repetitions into a trial plan |
| **Agent harness** | Controls how the model receives the task and uses tools |
| **Harbor environment** | Runs the trial on Modal, Docker, E2B, Daytona, or Morph |
| **Harbor orchestrator** | Starts the planned trials with the configured local concurrency |
| **AEC-Bench importer** | Validates completed results and writes `TrialRecord` records to the ledger |

For environment selection and local execution, see [Backends](/docs/advanced/backends).

## Install execution support

Install the Harbor extra before using `aec-bench run`:

```bash
pip install "aec-bench[execution]"
```

Morph also needs its provider extra:

```bash
pip install "aec-bench[execution,morph]"
```

Keep provider credentials in environment variables or the provider's authentication store. Do not put them in the experiment manifest.

## Dispatch and import

A live run follows one sequence:

1. Validate the manifest and selected backend.
2. Resolve the selected tasks and build the complete trial plan.
3. Write a generated Harbor job config.
4. Invoke `uv run harbor run -c <generated-config>`.
5. Locate the new Harbor job directory.
6. Run the optional post-verifier reviewer.
7. Validate and import the completed trials into the ledger.

Start the sequence through the AEC-Bench command rather than invoking the generated Harbor config yourself:

```bash
uv run aec-bench run --config experiment.yaml
```

The command reports the job directory, imported trial count, and duplicate count. A failed Harbor command stops the workflow before import.

## Configuration

The experiment manifest selects the Harbor environment and local orchestration concurrency:

```yaml
compute:
  backend: modal
  resource_limits:
    n_concurrent_trials: 4
  timeout_override: 600
```

Harbor service configuration stays with Harbor and the selected provider. The public manifest records the benchmark choice: backend, concurrency, and optional timeout override.

Use a dry run to inspect the selected tasks and exact trial plan without dispatching a job:

```bash
uv run aec-bench run --config experiment.yaml --dry-run
```

A dry run proves planning only. It does not test provider access, environment creation, agent execution, verifier execution, or import.

## Import an existing job

Use `aec-bench import` when a completed Harbor job directory already exists:

```bash
uv run aec-bench import jobs/<harbor-job-id>
```

The importer reads the Harbor results and trial artefacts, validates their task and execution records, and writes `TrialRecord` records. Re-importing identical records reports duplicates. If the same trial identity resolves to different ledger content, the import fails instead of overwriting the existing record.

Provider completion, agent failure, verifier evidence, and reviewer evidence remain distinct in the imported record. Do not treat a present result file or a completed provider job as proof that the task passed.

## Operational boundaries

- Harbor creates the execution environment and runs the generated job; AEC-Bench owns planning and ledger import.
- `aec-bench run` does not provide a detached job queue. Keep the calling process alive until Harbor returns.
- AEC-Bench does not add a second retry or pre-emption policy around Harbor.
- Trial provenance records the task, agent, environment, output, timing, and evaluation evidence needed for later analysis.
- Complete, valid trial records are the basis for comparison and leaderboard aggregation.
