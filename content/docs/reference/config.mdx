## `aec-bench.toml` — project root

Defines paths and defaults for a project. Placed at the repo root.

```toml
[project]
name = "my-bench"

[paths]
tasks      = "tasks"
templates  = "templates"
seeds      = "seeds"
ledger     = "artefacts/ledger"
feedback   = "artefacts/feedback"
datasets   = "artefacts/datasets"
jobs       = "jobs"

[compute]
backend = "modal"
```

All paths are relative to the project root. Omitted keys fall back to the defaults above.

The `aec-bench config` CLI manages per-user JSON path defaults. Project TOML stores path defaults and may contain `compute.backend`; config-backed runs select the backend from `experiment.yaml`, and inline runs use `--backend`.

## `task.toml` — per task

Every task directory has one. A typical file is:

```toml
version = "1.0"

[identity]
id = "019c2c7a-5a33-7b8d-a702-8f7f3e8c21aa"
key = "electrical/voltage-drop"
version = 3

[metadata]
lifecycle  = "active"            # proposed | active | deprecated | retired
visibility = "public"            # public | private | holdout
difficulty = "easy"              # easy | medium | hard
category   = "reasoning"
tags       = ["electrical", "AS-NZS-3008"]

[agent]
timeout_sec = 600.0

[verifier]
timeout_sec = 300.0

[environment]
extensions         = []
build_timeout_sec  = 600.0
cpus               = 2
memory_mb          = 4096
storage_mb         = 10240
allow_internet     = true
```

See [Tasks](/docs/core/tasks) for what lives alongside `task.toml` in a task directory.

## `experiment.yaml` — per run

A single experiment: which tasks, which agents, how to run them.

```yaml
experiment_id: exp-20260412-001
name: "Claude vs GPT electrical"
description: "Optional narrative description"

tasks:
  dataset:
    kind: repository
    dataset_id: electrical-core
    source_revision: 0123456789abcdef0123456789abcdef01234567
    manifest_path: artefacts/datasets/manifests/electrical-core/manifest.json
  include_patterns: ["electrical/*"]
  exclude_patterns: []
  domains:      ["electrical"]
  difficulties: ["easy", "medium"]
  lifecycle_filter: ["active"]
  visibility_filter: ["public"]

agents:
  - name: claude-tool-loop
    harness: tool_loop
    model: claude-sonnet-4-20250514
    parameters:
      max_turns: 12
    system_prompt_file: prompts/electrical.md   # optional

  - name: gpt4-direct
    harness: direct
    model: gpt-4.1
    parameters:
      max_tokens: 8192

compute:
  backend: modal
  timeout_override: 1200
  resource_limits:
    memory_mb: 8192

reviewer:                         # optional post-verifier LLM stage
  enabled: true
  required: true
  models:
    - name: primary-reviewer
      model: gpt-4.1-mini
      provider: auto
  fail_on_error: false

repetitions: 3
disable_verification: false
```

The `model` field supports `$ENV_VAR` expansion. The manifest parser accepts `harness` as the public synonym for the internal `adapter` field; generated YAML may still contain `adapter`.

The runner applies dataset task IDs, patterns, domain, and difficulty as intersections. A dataset-backed experiment contains an exact repository or bundle reference. Use `dataset config` to resolve a human label before you write the experiment. Run `dataset validate` first and inspect the dry-run plan.

`run plan --config` resolves the manifest into a persisted `ResolvedRunSpec`.
The saved condition contains exact task releases, agent conditions, compute and
repetition settings, verification and reviewer settings, visibility, and
execution policy. Environment-backed credentials remain named environment
references in the resolved condition.

The resolved `ExecutionPolicy` includes scheduler limits, retry policy, lease
timing, priority ageing, and scoped limits. The CLI planning path
resolves `max_concurrency` to `1`; this policy is persisted for inspection and
Python composition.

`compute.timeout_override` sits alongside `resource_limits` and overrides the per-task trial timeout.

The optional `reviewer` block runs after deterministic verification:

| Option | Meaning |
|--------|---------|
| `models` | One or more reviewer endpoints. Each can set `base_url`, `base_url_env`, `api_key_env`, `temperature`, `max_tokens`, and `stream_mode`. |
| `required` | Controls whether an enabled reviewer requires at least one configured model. |
| `fail_on_error` | Controls whether a reviewer execution error fails the run. |

Reviewer findings are separate from verifier rewards and human annotations.

## Harness configs

RLM and Lambda-RLM read authored files from the staged task workspace. Experiment YAML `parameters` override matching TOML values; host request limits can only tighten the resolved limits. Unknown keys and unsupported modes fail validation. See [configuration precedence](/docs/agents/configuration#report-configuration-precedence) and the [RLM guide](/docs/agents/rlm).

### `rlm.toml`

This example enables a guided report with bounded context and model work:

```toml
[template]
definition = "report_template.toml"
source_mapping = "sources.toml"
validation_rules = "checks.toml"

[guardrails]
token_budget = 100_000
max_iterations = 20
max_subcall_depth = 1

[execution]
scaffolding = true
context_limit = 128_000
compaction_threshold_pct = 0.85
hard_ceiling_pct = 0.95
max_parallel_workers = 4
```

| Block | Settings |
|-------|----------|
| `template` | `tier`, `definition`, `source_mapping`, `validation_rules`. A loaded template supplies guided report state. |
| `inputs.<name>` | `type`, `source`, `pre_parse`, `description` declare an input handle. |
| `hints` | `phases` and `prohibited` supply execution guidance. |
| `subcalls.<name>` | `enabled`, optional `custom_impl`, and `description` declare a typed subcall. |
| `guardrails` | `token_budget` defaults to 500,000; `max_iterations` to 100; `max_subcall_depth` to 1; `budget_warning_pct` to 80. Optional `max_subcalls`, `max_budget_usd`, and `billable_input_budget` use 0 for no additional cap. |
| `execution` | `scaffolding` defaults to true. `context_limit` defaults to 128,000 input tokens. Compaction and hard-ceiling fractions default to 0.85 and 0.95. `max_parallel_workers` defaults to 4. |
| `advisor` | `enabled`, `model`, `max_uses`, `max_response_tokens`, and `context_window`. See [Advisor](/docs/advanced/advisor). |

Optional `execution.compaction_model` and `execution.subcall_model` select secondary model routes. Omit them to use the main model. TOML has no `null` value; omit unset optional keys. Input-context limits must be positive, with `0 < compaction_threshold_pct < hard_ceiling_pct <= 1`.

### `lambda-rlm.toml`

Lambda-RLM reads `lambda-rlm.toml`, then falls back to `rlm.toml`, then condition values alone. A fallback file with RLM-only options fails validation. Use separate compatible files when a task supports both harnesses.

```toml
[template]
definition = "report_template.toml"
source_mapping = "sources.toml"
validation_rules = "checks.toml"

[planner]
context_window_chars = 100_000
max_branching_factor = 20

[review]
enabled = true
trigger = "always"
max_retries_per_source = 1
max_supplements_per_section = 1

[execution]
max_parallel_workers = 4

[guardrails]
token_budget = 100_000
```

| Block | Settings |
|-------|----------|
| `template` | `tier`, `definition`, `source_mapping`, `validation_rules` declare the report assets. |
| `planner` | `context_window_chars` defaults to 100,000 characters and `max_branching_factor` to 20. `accuracy_target`, `leaf_accuracy`, and `compose_accuracy` default to 0.80, 0.95, and 0.90. |
| `extract` | `k_candidates` defaults to 1; `temperature` to 0.7. `keep_candidates_artifact` retains extraction candidates when enabled. |
| `review` | `enabled` defaults to true and `trigger` to `always`. Other triggers are `uncertainty`, `consistency`, `both`, and `never`. Retry and supplement limits default to 1. |
| `uncertainty` | `lambda`, `min_confidence_eps`, `min_samples`, and `review_joint_threshold` control the joint uncertainty signal. See [extraction review](/docs/agents/configuration#lambda-rlm-extraction-review). |
| `structure_enforcement` | `enabled`, `max_retries`, and `validator_model` control an optional model check for required structure. The retry default is 2. |
| `grounding` | `check` is `default` or `off`; optional `custom_facts` supplies pattern checks. Grounding findings remain advisory. |
| `compose` | `mode` selects `orchestrated` or `agentic` composition. Agentic composition can reuse extracted values from a scratchpad. |
| `planning_phase` | With agentic composition, `enabled`, `sources`, and `extract_slots` seed the scratchpad. Optional `back_brief` and `scope_evolution` passes have their own sources, model, and output limit. These passes are inactive in orchestrated mode. |
| `sandbox` | `enabled` enables document and anchor access; `extractor_overrides` selects document extractors. `tool_use = true` is unsupported. |
| `execution` | `max_parallel_workers` bounds parallel work and defaults to 4. RLM context and compaction keys do not apply to this pipeline. |
| `guardrails` | `token_budget` defaults to 500,000 and counts all model phases. |
| `advisor` | Uses the same declared model and advice limits as RLM. |

`review.confidence_threshold` defaults to 0.6 and `review.consistency_threshold` to 0.7. `consistency` and `both` require `extract.k_candidates > 1`; a single-sample configuration fails before model work.

### Report assets

`template.definition` resolves relative to the harness file, or the workspace for condition-only configuration. `source_mapping`, `validation_rules`, and explicit `[boilerplate].path` values resolve relative to the template. All resolved paths must stay inside the actor workspace, including through symlinks.

A report template declares its sections in order:

```toml
# report_template.toml
[[sections]]
id = "findings"
title = "Findings"
input_mapping = ["inspection"]
writing_guidance = ["State the observed count and cite the source ID."]
fields = [{ name = "text", dtype = "str", required = true }]

[[sections]]
id = "summary"
title = "Summary"
depends_on = ["findings"]
fields = [{ name = "text", dtype = "str", required = true }]
```

Field types are `str`, `int`, `float`, `bool`, `list`, `dict`, and `table`. Source priorities use `input_mapping = { sources = ["inspection"], priority = { inspection = 1 } }`; lower numbers mean higher authority. Priorities can only refer to mapped sources. Section IDs must be unique, and dependencies must name existing sections without forming a cycle.

The mapping gives source IDs an explicit public path:

```toml
# sources.toml
[sources.inspection]
path = "documents/inspection.txt"
visibility = "public"

[sections.findings]
sources = ["inspection"]
```

Public writing rules have an ID, kind, message, and optional section and field scope. Error-level pattern failures block acceptance; warnings do not. A `prose` rule remains `unchecked` by deterministic validation; a model review can supply separate findings.

```toml
# checks.toml
visibility = "public"

[[rules]]
id = "observed-count"
kind = "required_pattern"
pattern = "12"
message = "State the recorded count of 12."
severity = "error"
```

Pattern kinds are `required_pattern` and `forbidden_pattern`; patterns must compile. Required fields and types are checked independently from these rules. The [synthetic example](/docs/agents/rlm#synthetic-inspection-example) also includes a public rubric with weighted dimensions, criterion categories, and reference scope.

### Section candidates

This Lambda-RLM example generates three drafts for the summary and synthesises one result:

```toml
[fill_section]
k_candidates = 3
temperature = 1.0
tournament_mode = "synthesis"
apply_to_sections = ["summary"]

[fill_section.synthesis]
synthesiser_model = "anthropic:claude-sonnet-4-6"
synthesis_mode = "plain"
max_input_tokens = 16_000
max_output_tokens = 2_000
```

Choose a `synthesiser_model` supported by the configured provider route. Secondary model settings cannot raise the provider client's per-call maximum. All candidate and synthesis calls count towards the run budget.

At `k_candidates = 1`, one section is generated. Larger K requires `tournament_mode = "synthesis"`; an empty `apply_to_sections` list applies it to all sections. Only plain synthesis is supported. The worker limit is `execution.max_parallel_workers`. Extraction samples and CLI whole-attempt `--best-of` are [separate controls](/docs/agents/rlm#optional-candidates-and-synthesis).

### Fixed constitutional parameters

Set `constitution.path` to a declared constitution file, or supply inline parameters. RLM accepts its parameter tables directly under `constitution`:

```toml
# rlm.toml
[constitution.information_minimality]
default_threshold = 2000
search_threshold = 10000
preview_length = 200
truncation_strategy = "metadata"

[constitution.state_persistence]
preserve_variables = true
preserve_scratchpad = true
compaction_strategy = "llm_summary"

[constitution.source_fidelity]
require_source_tracing = true
tbd_placeholder = "[TBD]"
gap_framing = "exclude"
```

Lambda-RLM uses `constitution.inline` and supports information previews and source fidelity:

```toml
# lambda-rlm.toml
[constitution.inline.information_minimality]
default_threshold = 2000
search_threshold = 10000
preview_length = 200
truncation_strategy = "head"

[constitution.inline.source_fidelity]
require_source_tracing = true
tbd_placeholder = "[TBD]"
gap_framing = "tbd"
```

Preview strategies are `metadata`, `head`, and `tail`. RLM state persistence supports `llm_summary`, `state_only`, and `full_reset`; task instructions, system policy, report state, and bindings remain protected. RLM also accepts progress nudge and stall thresholds under `constitution.progress_obligation`, and an initial mode under `constitution.earned_autonomy`. The initial modes are `constrained`, `guided`, and `autonomous`; they do not enable automatic promotion.

In a separate constitution file, use the parameter tables at the top level. Lambda-RLM rejects REPL state-persistence, progress, and autonomy tables. Constitutional model inference is unsupported for report execution; declare fixed parameters instead.

## `evolution.yaml`

Drives the evolution loop (see [Evolution](/docs/advanced/evolution) and [Agentic Variation](/docs/advanced/avo)):

```yaml
workspace_path: workspaces/voltage-drop-evo

models:
  classifier: env:AWS_HAIKU_MODEL_ID
  evolver:    env:AWS_SONNET_MODEL_ID

solver:
  name: solver-v1
  harness: rlm
  model: env:AWS_SONNET_MODEL_ID
  client:
    kind: bedrock
    settings: {}

generate:
  template: voltage-drop
  count: 10
  seed: 999
  difficulties: ["easy", "medium"]

tasks:
  domains: [electrical]
  include_patterns: ["electrical/*"]
  exclude_patterns: []

backend: local
batch_size: 5
max_cycles: 10
improvement_threshold: 0.01
stagnation_window: 5
strategy: hill_climb
structural_weight: 0.3
discipline_balanced: false
timeout: 1800
harness_config: experiment.yaml      # optional
```

`strategy: hill_climb` keeps moving towards the current best candidate. `strategy: qd` keeps strong candidates with different behaviours. `structural_weight` and `discipline_balanced` tune that quality-diversity comparison. The `solver` runs tasks, the classifier adds behavioural observations, and the evolver model proposes workspace changes through AVO.

The YAML composition creates separate selection and revision checks from the selected public tasks. Holdout qualification remains a separate operation.

## `suite.toml` — generated-suite config

Declares how `aec-bench generate suite` should select templates, allocate instances, and write generated task output:

```toml
name = "my-suite"
seed = 20260524

[coverage]
difficulties = { easy = 0.3333333333, medium = 0.3333333333, hard = 0.3333333334 }
min_tasks_per_discipline = 3

[templates]
include = ["electrical/*", "civil/*"]
user_dirs = []

[visibility]
mix = { all_given = 0.78, partial = 0.22 }

[tool_mode]
mix = { with_tool = 1.0 }

[instances]
per_task = 3
total_max = 200

[output]
dir = "tasks/generated/my-suite"
```

The `templates.include` entries match each template's logical `discipline/name` path, such as `electrical/voltage-drop`. `generate suite --dry-run` returns the planned counts by discipline, difficulty, visibility, and tool mode before writing task instances.

## Dataset manifest

Create semantic dataset manifests with `aec-bench dataset create`:

```json
{
  "schema_version": 2,
  "dataset_id": "electrical-core",
  "description": "Cable and power-system baseline",
  "tasks": [
    {
      "task_id": "electrical/voltage-drop/basic",
      "path": "tasks/electrical/voltage-drop/basic",
      "task_kind": "artifact"
    }
  ],
  "generation": null
}
```

The manifest defines which tasks belong to the dataset. `schema_version` identifies the JSON file format and is supplied by the library. Publication binds the selection to one exact Git source or detached bundle. See [Datasets](/docs/advanced/datasets).

## `swarm.yaml`

Swarm config adds parallel agents, a shared budget, and an archive that keeps strong candidates with different behaviours:

```yaml
task:
  workspace: ./workspaces/my-swarm
  task_path: tasks/electrical/voltage-drop

agents:
  count: 4
  default_model: au.anthropic.claude-sonnet-4-6

budget:
  max_cost_usd: 20.0
  eval_budget_usd: 5.0
  wind_down_threshold: 0.8
  final_threshold: 0.95

evaluation:
  timeout: 300
  backend: local

evolution:
  batch_size: 1
  improvement_threshold: 0.01

heartbeat:
  pivot_after: 5
```

Each worker uses AVO to propose a candidate, while shared selection checks and the manager own scoring and archive effects. See [Swarm](/docs/advanced/swarm) for the runtime model and [Agentic Variation](/docs/advanced/avo) for the proposer boundary.

## Prime environment args

Prime export commands take selection flags directly. Hosted eval and training commands can forward environment arguments into `load_environment(...)`:

```bash
uv run aec-bench prime eval \
  --remote-env owner/aec-suite \
  --hosted \
  --model "Qwen/Qwen3.5-4B" \
  --split eval \
  --difficulty medium \
  --harness stateful \
  --env-num-examples 10 \
  --seed 20260509 \
  --env-arg max_turns=20
```

Values passed through `--env-arg KEY=VALUE` are parsed as JSON where possible, so numbers and booleans keep their types.

Generated Prime environments apply task selection in this order: difficulty filter, deterministic split selection, optional seeded shuffle, then `num_examples`. Use `split=all` when you intentionally want the full exported slice.

## `configs/endpoints.toml`

In Prime Lab workspaces, endpoint aliases live in `configs/endpoints.toml` and are referenced by Prime commands and generated experiment configs. Keep provider credentials in environment variables or the provider's own auth store, not in this file.
