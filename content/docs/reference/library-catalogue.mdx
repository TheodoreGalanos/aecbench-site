The catalogue is the public data bridge between the Python library and this site. It contains built templates and proposed seed tasks.

## Export

From the aec-bench library checkout:

```bash
uv run aec-bench library export --pretty
```

The default output is:

```text
artefacts/library-catalogue.json
```

Use stdout for CI or inspection:

```bash
uv run aec-bench library export --stdout --pretty
```

## Schema

The v1 export has top-level metadata, counts, templates, and seeds. This shortened example shows its metadata and aggregate totals:

```json
{
  "schema_version": 1,
  "generated_at": "<ISO-8601 timestamp>",
  "library_version": "<library version>",
  "library_commit": "<git commit>",
  "counts": {
    "total_templates": 352,
    "total_seeds": 284
  },
  "templates": [],
  "seeds": []
}
```

Each entry includes:

| Field | Meaning |
|-------|---------|
| `task_id` | Stable slug used by docs and discipline pages |
| `discipline` | One of civil, electrical, ground, maritime, mechanical, structural |
| `category` | Machine-readable category slug |
| `task_name` | Display title |
| `description` and `long_description` | Short and expanded public descriptions |
| `standards` | Named standards or method references when available |
| `inputs` and `outputs` | Public IO contract, units, and tolerances where known |
| `status` | `built` for templates, `proposed` for seed tasks |
| `difficulty_tiers` | Supported easy, medium, hard presets for built templates |
| `tool_mode` | Whether generated tasks expose tools |
| `archetype_count` | Number of sampling archetypes for built templates |

## Generation identity

The catalogue describes public template families. Each generated task has its own deterministic provenance: template source digest, seed, stable instance index, difficulty, and visibility. Keep those fields with the generated task to preserve the identity of an existing instance across catalogue refreshes.

## Site sync

The task browser uses the last successfully synced snapshot: 184 built templates and 284 proposed seeds across five disciplines. The upstream library export is authoritative for current template and seed counts.

The current library export includes Maritime, but the task browser accepts only five disciplines. Add Maritime to the task-browser catalogue contract and routes before syncing the six-discipline file. The leaderboard can remain on its existing five-domain contract until ranked Maritime trial data exists.

From the site checkout:

```bash
pnpm sync:catalogue
```

The script reads `../aec-bench/artefacts/library-catalogue.json` by default, validates it with the site Zod schema, and writes:

```text
data/library-catalogue.json
```

Override the library checkout path when needed:

```bash
AEC_BENCH_ROOT=/path/to/aec-bench pnpm sync:catalogue
```

## Public scope

The catalogue is for public library documentation. It should describe:

- Built-in templates and proposed seed tasks
- Engineering discipline, category, standards, inputs, outputs, and difficulty
- Reproducible generation and benchmark metadata

Limit the catalogue to the public benchmark surface. Keep local run outputs, private customer material, scratch workspaces, and intentionally excluded task families outside it.

## Versioning

`schema_version` protects the site build. If the library changes the catalogue shape, update the site schema and docs in the same change. If only counts or entries change, regenerate and sync the JSON artefact.
